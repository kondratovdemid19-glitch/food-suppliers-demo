# Снабжение

Прототип поиска поставщиков для пищевого бизнеса. Часть 2 тестового задания.

Помогает выбрать категорию и город, собрать короткий список поставщиков и подготовить вопросы перед закупкой. Четыре реальные компании, официальные источники и контакты, без вымышленных цен и рейтингов.

## Запуск

Требуется Node.js 22.12+ и npm.

```sh
npm ci
npm run dev
```

Адрес будет показан в терминале. Для готовой сборки:

```sh
npm run build
npm run preview
```

## Что можно проверить

1. В категории «Упаковка» выбрать Новосибирск — останется КОМУС-упаковка.
2. Ввести отсутствующий товар — появится объяснение и сброс фильтров.
3. Добавить ПУРАТОС в сравнение, сменить категорию, добавить КОМУС — оба сохранятся в сравнении.
4. Выбрать три компании — у четвёртой добавление заблокируется, пока не снят один из выбранных.
5. Написать заметку, обновить страницу — заметка останется в этом браузере.
6. Раскрыть «Источники и документы» — перейти на официальный сайт.

## Проверки

```sh
npm audit
npm test
npm run build
```

Девять сценариев в jsdom: данные и источники, совместные фильтры и пустое состояние, нечувствительность к регистру, неизвестная география, сохранение сравнения при фильтрации, ограничение сравнения, сохранение заметок и безопасный текст, повреждённое и недоступное хранилище. Сборка проверяет TypeScript и создаёт статический результат в `dist`.

Текущая проверка на 01.11.2026: 9/9 сценариев прошли на Vitest 4.1.12, сборка выполнена на Vite 7.3.7, `npm audit` — 0 уязвимостей. Vitest обновлён после проверки зависимостей; принудительные исправления не использовались. Визуальная проверка в настоящем браузере пока не проводилась по ограничению на этой стадии работы. Перед отправкой нужно просмотреть desktop/mobile.

## Данные

Снимок открытых официальных сайтов от 01.11.2026, не живой поиск в интернете. Источники и границы данных — в [docs/SOURCES.md](docs/SOURCES.md). Каталог намеренно небольшой, его можно расширить в `src/data.ts`.

География описывает подтверждённое присутствие, не зону доставки. Фильтр по региону исключает компании с неизвестной географией; неизвестное не превращается в обещание. Пустой результат не означает отсутствие поставщиков на рынке. Расчёт цены, доступность остатков, качество поставщика и действительность документов на артикул не проверялись.

Заметки хранятся в localStorage этого браузера, без отправки на сервер. Они не синхронизируются между устройствами и исчезнут при очистке данных сайта. При ошибке сохранения интерфейс сообщает об этом. Внешние ссылки открываются в новой вкладке; нажатие на телефон/почту передаёт действие установленному приложению. Прототип сам ничего не отправляет.

## Почему такой формат

Веб-каталог открывается без установки, показывает варианты одновременно и удобен для предметного сравнения. Без регистрации можно пройти весь основной сценарий. Для небольшого каталога выбран TypeScript + Vite без интерфейсного фреймворка: минимум зависимостей и готовый статический сайт. Сервер и авторизация не нужны для демонстрации основной пользы.

## Публикация

Адрес кода: https://github.com/kondratovdemid19-glitch/food-suppliers-demo

Адрес прототипа: https://kondratovdemid19-glitch.github.io/food-suppliers-demo/

Публикация выполняется через GitHub Pages (`gh-pages`) после проверок зависимостей, сценариев и сборки. Путь подкаталога уже задан в `vite.config.ts`.

1. Опубликовать исходники этой папки в отдельный репозиторий. `node_modules` и `dist` исключены из Git.
2. Подключить репозиторий к статическому хостингу: команда сборки `npm run build`, каталог публикации `dist`, Node.js 22.12+.
3. Открыть опубликованный адрес, пройти сценарии выше на телефоне и компьютере.
4. Передать HR адрес прототипа, адрес репозитория и текст из [HR.md](HR.md).

Для размещения в другом подкаталоге изменить `base` в `vite.config.ts`. Для размещения в корне сайта задать `base: "/"`, затем пересобрать.

## Структура

- `src/data.ts` — каталог и официальные источники.
- `src/app.ts` — интерфейс, поиск, сравнение и заметки.
- `src/style.css` — адаптивное оформление.
- `tests/app.test.ts` — пользовательские сценарии.
- `docs/DECISIONS.md` — обоснование и принятые решения.


Publishing layout: source code is in `main`; only the contents of `dist` and `.nojekyll` are published from `gh-pages` (root). Run the audit, tests and build before updating `gh-pages`.
