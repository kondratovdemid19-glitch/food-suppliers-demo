# Снабжение

Рабочий прототип поиска поставщиков продуктов, ингредиентов и упаковки. Задание для AI-инженера Goulash.Tech: помочь закупщику найти подходящие компании, собрать информацию и решить, с кем связаться.

**[Открыть прототип](https://kondratovdemid19-glitch.github.io/food-suppliers-demo/)**

## Основной сценарий

1. Введите товар и город или выберите пример «Упаковка · Новосибирск».
2. Откройте условия и источники нужных компаний.
3. Добавьте до трёх поставщиков в список и сравните условия рядом.
4. Подготовьте запрос: уточните товар, объём и адрес. Текст можно отредактировать, скопировать или скачать. Автоматической рассылки нет.
5. Сохраните заметку и статус контакта. Они, как и выбор компаний, останутся в этом браузере после обновления.

Сравнение выгружается в CSV с кодировкой для Excel. Начало формулы в пользовательском тексте экранируется. Если доступ к буферу обмена запрещён, можно скачать запрос или скопировать его вручную.

## Данные и границы

Шесть компаний: ПУРАТОС, METRO B2B, КОМУС-упаковка, ВкусВилл Бизнес, OSQ Group, ЭФКО. У каждой есть официальные источники и индивидуальная дата проверки. Каталог неполный. Это снимок открытых источников, а не поиск по всему интернету.

География означает подтверждённое присутствие компании; доставку до адреса нужно согласовать отдельно. Отсутствующие цены, минимальные партии и документы не выдуманы. Сервис не ранжирует поставщиков по неизвестным условиям и не обещает их надёжность. Смешанные категории в сравнении помечаются отдельно.

Подбор работает по категории, словам продукции, названию и городу. В запросе вида «упаковка для доставки в Новосибирске» выделяются город и категория. Это разбор по правилам: внешняя языковая модель не используется. Такой выбор позволяет проверить основной процесс закупки без платного ключа, утечки данных и выдуманных рекомендаций.

## Устройство

- TypeScript + Vite: интерфейс, подбор, сравнение и локальное рабочее состояние.
- Python + SQLite: каталог и HTTP API только для чтения; параметризованные запросы, ограничения длины и числа результатов, проверка категорий.
- `data/suppliers.json`: общий набор данных для интерфейса и сервера.
- Заметки и статусы не передаются серверу. Авторизация и общая командная база в этот прототип не входят.

На GitHub Pages интерфейс работает со встроенным каталогом. Серверная часть запускается отдельно и не требуется для доступности опубликованного прототипа. При подключении API интерфейс принимает только записи, совпадающие с проверенным набором; при тайм-ауте остаётся локальная копия и показывается состояние подключения. Это явная граница текущей демонстрации, а не имитация серверного хранения заметок.

## Запуск

Node.js 22.12+ и Python 3.9+; сторонних Python-зависимостей нет.

```sh
npm ci
npm run build
python3 -m server.app
```

Откройте `http://127.0.0.1:5198/food-suppliers-demo/`. Для разработки интерфейса: `npm run dev`.

### API

- `GET /api/health` — состояние и число записей.
- `GET /api/suppliers?q=закваска&category=ingredients` — поиск продукции.
- `GET /api/suppliers?category=packaging&region=Новосибирск` — категория и регион.
- `limit`: от 1 до 50. Длинные, неизвестные и повторяющиеся параметры возвращают 400; изменение данных через POST — 405.

Сервер строит SQLite из канонического JSON при запуске; повторный запуск не создаёт дублей. База содержит только публичный каталог. В Docker процесс работает от непривилегированного пользователя. `PORT` задаёт порт, `CATALOG_DB` — расположение базы. Для отдельного API задайте в `index.html` метатег `catalog-api` с адресом сервиса; в поставленной сборке он не задан.

## Публикация

Исходники находятся в `main`, содержимое `dist` публикуется в `gh-pages`. Путь Vite — `/food-suppliers-demo/`; Python-сервер также обслуживает этот путь. Docker собирает интерфейс и запускает Python API. Изменение публикации не отправляет уведомления работодателю в чат.
